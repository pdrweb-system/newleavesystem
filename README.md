# ระบบแจ้งผลการเลื่อนเงินเดือนครู

เว็บให้ครูเข้าไปดูและบันทึก PDF "หนังสือแจ้งผลการเลื่อนเงินเดือน" ของตัวเอง
แอดมินกรอกตัวเลข → ผู้อำนวยการ (ผอ.) อนุมัติ → ระบบเผยแพร่ให้ครูเห็น พร้อมใส่ภาพลายเซ็น ผอ. อัตโนมัติ

**ข้อมูลเงินเดือนรายบุคคลเป็นความลับ** สิทธิ์ทั้งหมดบังคับที่ฐานข้อมูล (RLS) ไม่ได้พึ่งการซ่อนปุ่มในหน้าเว็บ

- หน้าเว็บ: HTML + JavaScript ล้วน (ไม่มีขั้นตอน build) วางบน host แบบ static ที่ใช้ HTTPS ได้ทุกเจ้า
- ฐานข้อมูล ล็อกอิน ไฟล์ลายเซ็น และ Edge Functions: Supabase โปรเจกต์ `salary-notice`
- PDF: ใช้ "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์ (1 คน = 1 หน้า A4)
- สเปกเต็มอยู่ที่ [`docs/SPEC.md`](docs/SPEC.md)

## บทบาทและขั้นตอนต่อรอบ

| ขั้น | ใคร | ทำอะไร | หน้า |
|---|---|---|---|
| 1 | แอดมิน | สร้างรอบ กรอกตัวเลขของครูทุกคน (ระบบเสนอค่าให้ แก้ทับได้) ดูตัวอย่างใบ แล้วกด "ส่งให้ ผอ. อนุมัติ" | `admin.html` |
| 2 | ผอ. | ตรวจตารางสรุป (ช่องที่ต่างจากค่าที่ระบบคำนวณมี ⚠) แล้ว "อนุมัติและเผยแพร่" หรือ "ตีกลับ" พร้อมเหตุผล | `director.html` |
| 3 | ครู | ล็อกอินด้วยรหัสประจำตัว → ดูใบ → "บันทึกเป็น PDF" | `teacher.html` |

- รอบที่เผยแพร่แล้วแก้ตัวเลขไม่ได้: ถ้าต้องแก้ ผอ. กด "ถอนการเผยแพร่" (ต้องใส่เหตุผล) → แอดมินแก้ → ส่งใหม่ → ผอ. อนุมัติอีกครั้ง
- ใบที่อนุมัติแล้วเก็บ "ภาพถ่าย" ของลายเซ็น ชื่อ ผอ. ชื่อโรงเรียน สังกัด ณ วันอนุมัติ แก้การตั้งค่าภายหลังใบเก่าจะไม่เปลี่ยน
- ทุกการเปลี่ยนแปลงและทุกการดาวน์โหลด/พิมพ์ถูกบันทึกใน audit log (แอดมินและ ผอ. ดูได้ แก้/ลบไม่ได้)

## โครงสร้างไฟล์

```
index.html              ล็อกอิน (ครูกรอกรหัสประจำตัว ระบบต่อเป็น {รหัส}@school.invalid)
change-password.html    บังคับตั้งรหัสใหม่ตอนล็อกอินครั้งแรก/หลังถูกรีเซ็ต
admin.html              แอดมิน: รอบ, ครู/บัญชี, ตั้งค่าโรงเรียน+ลายเซ็น, บันทึกการใช้งาน
director.html           ผอ.: รออนุมัติ, ทุกรอบ, บันทึกการใช้งาน
teacher.html            ครู: รายการใบของตัวเอง
notice.html             หน้าใบแจ้ง/พิมพ์ (?round=…&all=1 | &teacher=… | &print=1 | ?demo=1 ข้อมูลสมมติ)
assets/                 JavaScript, CSS, ฟอนต์ (self-host), supabase-js (เก็บไว้ในโปรเจกต์ ไม่โหลดจาก CDN)
assets/config.js        URL ของ Supabase + publishable key (ค่าสาธารณะ)
supabase/migrations/    โครงสร้างฐานข้อมูล สิทธิ์ RLS ฟังก์ชัน trigger storage (รันตามลำดับชื่อไฟล์)
supabase/functions/     Edge Functions: admin-create-user, admin-reset-password
supabase/seed/          สร้างบัญชีแอดมิน/ผอ. ครั้งแรก, ล้างข้อมูลทดสอบก่อนใช้งานจริง
supabase/tests/         ชุดทดสอบสิทธิ์ (RLS) และทั้ง flow
tests/                  ทดสอบสูตรคำนวณ และทดสอบหน้าเว็บ (จำลอง Supabase)
docs/                   สเปกและไฟล์อ้างอิง (ข้อมูลสมมติ)
```

## เผยแพร่หน้าเว็บ

อัปโหลดเฉพาะไฟล์หน้าเว็บ: `*.html` และโฟลเดอร์ `assets/` (ไม่ต้องอัปโหลด `supabase/`, `tests/`, `docs/`)
ขึ้น host แบบ static ที่ใช้ HTTPS เช่น Netlify, Cloudflare Pages หรือเซิร์ฟเวอร์ของโรงเรียน

หลังได้โดเมนแล้ว: Supabase Dashboard → Authentication → URL Configuration → ตั้ง **Site URL** เป็นโดเมนของเว็บ

> ไฟล์ในหน้าเว็บมีแค่ publishable key ซึ่งเปิดเผยได้ ความปลอดภัยอยู่ที่ RLS
> ห้ามใส่ `service_role` / secret key ในไฟล์ใดของหน้าเว็บหรือ commit เข้า repo

## ตั้งค่าใน Supabase Dashboard (ทำครั้งเดียว ตั้งผ่าน SQL ไม่ได้)

- Authentication → Sign In / Providers → ปิด **Allow new users to sign up** (บัญชีสร้างโดยแอดมินเท่านั้น)
- Authentication → Sign In / Providers → Email → **Minimum password length** = 8
- เปิด **Leaked password protection** ถ้าแผนที่ใช้รองรับ

## ติดตั้งใหม่ทั้งหมด (กรณีย้าย/สร้างโปรเจกต์ใหม่)

ต้องมี [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started)

```bash
supabase login
supabase link --project-ref <project-ref>
supabase db push                                    # รัน supabase/migrations/ ทั้งหมด
supabase functions deploy admin-create-user admin-reset-password
```

1. ตั้งค่า Dashboard ตามหัวข้อด้านบน
2. สร้างบัญชีแอดมินและ ผอ.: เปิด `supabase/seed/create_staff_account.sql` ใน SQL editor
   แก้ชื่อล็อกอิน/บทบาท/รหัสชั่วคราว แล้วรัน (ทำ 2 ครั้ง) — ห้าม commit ไฟล์ที่ใส่รหัสจริง
3. แก้ `assets/config.js` ให้เป็น URL และ publishable key ของโปรเจกต์ใหม่ (Dashboard → Project Settings → API Keys)
4. แอดมินล็อกอิน → ตั้งค่าโรงเรียน → อัปโหลดลายเซ็น ผอ. (PNG พื้นโปร่ง ≤ 500 KB) → เพิ่มครูและสร้างบัญชี

## สำรองข้อมูล

แผน Free **ไม่มี backup ที่ดาวน์โหลดหรือกู้คืนเองได้** (backup รายวันมีให้ตั้งแต่แผน Pro)
Supabase แนะนำให้ export เองด้วย `supabase db dump` แล้วเก็บไว้นอก Supabase
ควรทำอย่างน้อย **หลังเผยแพร่ทุกรอบ** และก่อนแก้ไขระบบ

```bash
# connection string: Dashboard → Connect → Session pooler (ใส่รหัสผ่านฐานข้อมูล)
supabase db dump --db-url "$DB_URL" -f roles.sql --role-only
supabase db dump --db-url "$DB_URL" -f schema.sql
supabase db dump --db-url "$DB_URL" -f data.sql --use-copy --data-only
```

- ไฟล์ `data.sql` มีเงินเดือนของทุกคนและบัญชีผู้ใช้ **ต้องเข้ารหัสก่อนเก็บ** (เช่น zip/7-Zip แบบตั้งรหัส AES) และเก็บในที่ที่เฉพาะแอดมินเข้าถึง
- ไฟล์ลายเซ็นใน Storage **ไม่อยู่ใน dump** ให้ดาวน์โหลดเก็บแยก (Dashboard → Storage → bucket `signatures`)
- กู้คืนไปยังโปรเจกต์ใหม่ (ตาม [Backup and Restore using the CLI](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)):
  1. สร้างโปรเจกต์ใหม่ แล้วรัน
     `psql --single-transaction -v ON_ERROR_STOP=1 -f roles.sql -f schema.sql -c 'SET session_replication_role = replica' -f data.sql -d "$NEW_DB_URL"`
  2. dump ไม่รวมสิ่งที่ระบบนี้เพิ่มไว้ในสคีมา `auth` และ `storage` ต้องรันซ้ำใน SQL editor:
     ไฟล์ `supabase/migrations/20261021124257_storage.sql` ทั้งไฟล์ (policy ของไฟล์ลายเซ็น)
     และคำสั่ง `create trigger on_auth_password_changed …` ท้ายไฟล์ `supabase/migrations/20261021125351_auth.sql`
  3. อัปโหลดไฟล์ลายเซ็นกลับด้วยชื่อเดิม → deploy Edge Functions → ตั้งค่า Dashboard → แก้ `assets/config.js`
  4. รัน `supabase/tests/rls_test.sql` ยืนยันสิทธิ์ก่อนเปิดใช้
  - ขั้นตอนกู้คืนยังไม่ได้ซ้อมกับโปรเจกต์จริง ควรซ้อม 1 ครั้งกับโปรเจกต์ทดลองก่อนต้องใช้จริง

## ⚠️ โปรเจกต์แผน Free ถูกพักเมื่อไม่มีการใช้งาน

Supabase พักโปรเจกต์ Free ที่มีการใช้งานน้อยในรอบ 7 วัน (ส่งอีเมลเตือนล่วงหน้าประมาณ 1 สัปดาห์)
ระบบนี้ใช้ปีละ 2 ครั้ง จึง **ถูกพักแน่นอน** ระหว่างรอบ

- กดเปิดคืนได้ที่ Dashboard → โปรเจกต์ → **Resume project** ข้อมูลไม่หาย แต่ **ต้องทำภายใน 90 วัน** หลังถูกพัก
- เกิน 90 วันแล้วเปิดคืนจาก Dashboard ไม่ได้ ต้องดาวน์โหลด backup ไปกู้ในโปรเจกต์ใหม่ (URL และ key เปลี่ยน ต้องแก้ `assets/config.js`)

ทางเลือก (เลือกอย่างใดอย่างหนึ่ง):
1. อัปเกรดเป็นแผน Pro: ไม่ถูกพัก และมี backup รายวัน 7 วัน (มีค่าใช้จ่ายรายเดือน)
2. ตั้งเตือนในปฏิทินให้แอดมินเข้า Dashboard กด Resume ทุก 2 เดือน และ dump ข้อมูลเก็บไว้เสมอ
3. ตั้งงานอัตโนมัติเรียกระบบทุกวันเพื่อกันการพัก (ยังไม่ได้ทำ ต้องเพิ่มฟังก์ชันเล็ก ๆ และตัวตั้งเวลาเช่น GitHub Actions)

อ้างอิง: [Project Pausing](https://supabase.com/docs/guides/platform/free-project-pausing), [Database Backups](https://supabase.com/docs/guides/platform/backups)

## ความปลอดภัยและข้อมูลส่วนบุคคล

- ครูเห็นเฉพาะใบของตัวเองในรอบที่เผยแพร่แล้ว; ครูที่ถูก "ปิดใช้งาน" ไม่เห็นอะไรเลยทันที
- แอดมินรีเซ็ตรหัสได้เฉพาะบัญชีครู (รหัสแอดมิน/ผอ. รีเซ็ตใน Dashboard) เพื่อไม่ให้แอดมินสวมสิทธิ์ ผอ.
- ล็อกเอาต์อัตโนมัติเมื่อไม่ใช้งาน 30 นาที, session หายเมื่อปิดแท็บ, ไม่เก็บตัวเลขเงินเดือนในเครื่อง
- ภาพลายเซ็นเปิดผ่านลิงก์อายุ 5 นาที ครูเปิดได้เฉพาะไฟล์ที่รอบซึ่งเผยแพร่แล้วอ้างถึง
- PDF ที่ครูบันทึกแล้วอยู่ในเครื่องของครู ระบบควบคุมต่อไม่ได้ (หน้าเว็บมีคำเตือนเอกสารลับ)
- ห้ามใส่ข้อมูลจริงในตัวอย่าง ข้อมูลทดสอบ หรือ repo
